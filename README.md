## WooCommerce 主机和普通 WordPress 主机差在哪

多数主机商的方案是为通用 WordPress 站设计的，博客和静态站用着没问题。WooCommerce 店有三样额外的东西：体积大的产品目录、必须安全而且快的结账流程、以及随时可能到来的流量尖峰。购物车、结账、账户页不能被缓存，这条限制在 WooCommerce 官方文档和多家主机商的技术说明里被独立复述过，它直接决定了你不能只买一个“WordPress 主机”就完事。

具体到五个规格，官方的说法是这样的：

1. **PHP worker。** 每个访客访问、每次结账，后台都占用一个 PHP worker。官方建议从提供 5–10 个专用 worker 的主机看起。
2. **对象缓存。** 把产品描述、价格、SKU、库存这类数据库查询结果存下来，避免每次请求都回查数据库。没有这一层，PHP worker 会被反复的数据库查询拖住。
3. **CDN。** 要同时覆盖静态资源（产品图）和已经渲染好的 HTML 页面。页面是 PHP worker 辛苦拼出来的，CDN 能把它存下来直接发出去，worker 才腾得出手干别的。
4. **纵向扩展。** 邮件、投放、达人推荐都可能让流量在几小时内翻三倍，扩内存和 CPU 的过程不该需要你手动迁移。
5. **WooCommerce 专属技术支持。** 通用 WordPress 支持只是起点，能不能读懂 WooCommerce 的报错栈是另一回事。

另一套口径来自技术社区的实际测试经验，和上面的官方说法不是一回事，别混着当“官方要求”：内存 2GB 起步、生产环境建议 4GB（1GB 会频繁 OOM）；CPU 2 核以上，高并发结算时单核是明显瓶颈；NVMe SSD 优先，数据库读写频繁，磁盘 I/O 直接影响 TTFB；系统环境 PHP 8.0+、MySQL 8.0+ 或 MariaDB 10.6+。结论是生产环境 2 核 4GB 起步，2 核 2GB 只适合开发测试。

这套门槛放到 RackNerd 这种自管 VPS 上会有一个变化：**PHP worker 数量不是一个套餐参数**，而是你在 PHP-FPM 里设的 `pm.max_children`，能开多少取决于总内存和每个进程的实际占用。所以买 VPS 时该看的指标变成了内存和 CPU 核数，worker 数是你配出来的结果。这也意味着 4GB 内存的那档留给你调优的空间比“主机商送你 5 个 worker”要大，前提是你愿意进 SSH。

## 什么时候该换掉现在这台主机

WooCommerce 官方列了一组判断信号，比“感觉有点慢”可靠得多。任何一条持续成立，就说明当前主机在拖你的生意：

- **结账页的 TTFB 长期超过 800ms。** 这是首字节时间，不是整页加载时间。结账页不能被缓存，它慢就一定是 PHP 或数据库在执行层面出了问题。
- **产品数到 5,000 个、或订单数到 10,000 笔之后，WordPress 后台明显变慢。** 这说明数据库查询量已经超出当前配置的舒适区。
- **促销期间网站变慢或崩过一次，哪怕只有一次。** 典型表现是访客加载时看到 “502 Bad Gateway”。
- **技术支持让你“先停用插件”来排查问题。** 官方把这句写进了换机信号里，理由是对方没能力在不影响你生意的前提下定位根因。
- **你因为怕影响性能而犹豫要不要装某个插件。** 一个能带来转化的插件，不该因为主机跑不动而被否掉。
- **你需要 SSH 但主机不给。** 十分钟的活会变成三小时。
- **一次成功的促销之后，你收到了超量账单。**

## 从裸 VPS 到能收钱的 WooCommerce

RackNerd 交付的是一台空机器，八步能跑通：

1. 下单时选 Ubuntu 24.04 或 Debian 13 镜像，机房按 ping 测试结果定。
2. 收到 IP 和 root 密码后登录，装宝塔面板或 LNMP 一键包，得到 Nginx + PHP 8.x + MySQL 8.0。
3. 新建站点、绑定域名，申请 Let's Encrypt 免费证书。
4. 装 WordPress，填数据库信息完成安装。
5. 后台插件库搜 “WooCommerce”，安装激活，按向导配置货币、运费、支付方式。
6. 装对象缓存：Redis 服务加 Redis Object Cache 插件，这一步是把数据库查询从每次请求里摘出去的关键。
7. 装页面缓存插件（WP Rocket 或 LiteSpeed Cache），购物车、结账、账户页记得加进排除列表，这三页不能缓存。
8. 接 Cloudflare 做 CDN，然后自己走一遍完整下单流程，确认支付网关真的能收到钱。

第 6、7 步是最容易被跳过、又最影响结账速度的两步。TTFB 从 800ms 压到 200ms 以内，靠的通常就是页面缓存加对象缓存这两层，而不是换更贵的机器。
